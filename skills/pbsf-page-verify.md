# pbsf-page-verify — PC 页面改完必须用浏览器验证（修改与验证必须分开）

**新增/编辑任何 PC 端页面（列表页、编辑页、详情页、弹窗、组件）后，必须用 chrome-devtools MCP 连接真实浏览器做客观验证**，不能只看代码"觉得对"。

**核心红线：修改和验证必须分开，严禁自改自审。** 自己刚写的代码自己审 = 确认偏差，会自动忽略报错、把"看起来对"当"验证通过"，**完全没有意义**。

---

## 为什么自改自审没意义

- **确认偏差**：代码是自己写的，验证时大脑会预设"它是对的"，于是只看 happy path、扫一眼截图就放过，红框/报错/错位视而不见。
- **形式化验证**：跑一遍、点一下、截一张图、自我宣告"没问题"——这不是验证，是走过场。
- **客观证据缺失**：没接浏览器、没看控制台、没看网络请求，结论全凭脑补。

→ 验证必须基于**浏览器里的客观可观测事实**（控制台日志、网络状态码、DOM、截图、交互后真实变化），且验证者要和修改者**分离**。

---

## 三步工作流（强制）

```
① 修改阶段    写/改代码（Agent A 或主会话）
        ↓ 写完，明确停手，不要自我宣告"应该没问题"
② 验证阶段    用 MCP 连浏览器，按清单逐项核验客观证据（独立验证 Agent）
        ↓ 发现问题
③ 修复循环    回到 ① 改 → 再回 ② 验，循环到客观证据全绿
```

**断点必须清晰**：① 和 ② 之间要有明确切换，不能边写边说"这段应该 OK"。每次进入 ② 都重新假设"页面可能是坏的"，让证据说话。

---

## 怎么"分开" —— 两条路径，按情况选

### 路径 A（强推荐）：独立验证 subagent

写完代码后，用 `Agent` 工具**启动一个全新的验证 subagent**，把验证工作交给它：

```
Agent({
  subagent_type: 'general-purpose',
  description: '验证 XX 页面',
  prompt: `
    打开 http://localhost:14396/#/xxx（如需登录先用对应 authorize code 走 /authorize?code=...），
    验证以下功能，只报告客观证据，不要修改任何代码：
    1. 页面能否正常打开（截图 + 控制台是否有 error）
    2. 列表是否加载成功（网络请求状态码、表格是否有数据行）
    3. 搜索/新增/编辑/删除各点一遍，观察交互是否生效
    4. 布局有无错位、文字有无溢出/截断异常
    报告：每条给"通过/失败 + 证据（截图描述、控制台错误原文、状态码）"。
  `
})
```

**为什么有效**：subagent 拿到的是全新上下文，**没有作者偏差**——它不知道页面怎么写、作者的意图，只看浏览器里的结果。修改者 ≠ 验证者，这是真正的"分开"。

> subagent 同样可以用 chrome-devtools MCP 工具（`navigate_page`/`take_screenshot`/`list_console_messages`/...）。它只负责验证、只读不写代码，符合"修改和审核必须分开"。

### 路径 B（次选）：同会话强制切换"验证模式"

如果场景小、不想起 subagent，**同会话内也必须显式切模式**：

1. 写完代码后**停手**，明说"进入验证模式"。
2. 强制假设代码是错的，**只信浏览器证据**：打开页面、查控制台、查网络、点击交互、截图。
3. 把发现的每个问题列成清单（含证据），再切回"修改模式"逐个修。
4. 改完再切"验证模式"重跑，**直到清单全绿**。中间不许自我肯定。

路径 B 的风险是仍有偏差，所以**复杂页面/上线前/改了核心逻辑时，强制走路径 A**。

## 必须用的 MCP 工具（chrome-devtools）

按全局约定，"打开 URL"必须用 chrome-devtools MCP（`navigate_page`/`new_page`），不要用 `Start-Process` 起系统浏览器。验证阶段的核心工具：

| 工具 | 看什么（客观证据） |
|---|---|
| `navigate_page` / `new_page` | 打开目标路由 URL |
| `list_console_messages` | **控制台有无 error/warn**（types=['error']）——最硬的"页面没炸"证据 |
| `list_network_requests` | **接口状态码**：业务接口是否 2xx、有无 4xx/5xx、有无 401 跳登录 |
| `take_snapshot` | 抓 a11y 树，确认关键 DOM 节点存在（按钮、表格、表单项） |
| `take_screenshot` | 实际渲染：布局是否错位、文字是否溢出、表格列宽是否合理（配合 [[pbsf-table-column-width]]） |
| `click` / `fill` / `fill_form` | 触发交互：搜索、打开弹窗、提交表单 |
| `wait_for` | 等待关键文字/元素出现，确认异步加载完成 |
| `evaluate_script` | 必要时读 DOM/数据状态做断言 |

**全部基于客观输出**，而不是"我看了下代码应该对"。

## 验证清单（按页面类型）

### 列表页
- [ ] 页面打开，控制台 0 error
- [ ] 列表接口 2xx，表格渲染出数据行（或空态正确）
- [ ] 搜索条件生效：输入关键词/选字典/选日期 → 点查询 → 列表刷新
- [ ] 重置按钮清空条件
- [ ] 新增按钮能打开弹窗/跳编辑页
- [ ] 编辑能回显数据
- [ ] 删除有二次确认，成功后列表刷新
- [ ] 分页切换、pageSize 切换正常
- [ ] 表格列宽合理：长内容该省略的省略、没大面积留白也没横向溢出（见 [[pbsf-table-column-width]]）

### 编辑页/新增弹窗
- [ ] 表单打开，必填项校验生效（提交空表单看是否拦住）
- [ ] 各类字段交互正常：下拉能选、日期能选、上传能传、字典能切
- [ ] 提交接口 2xx，成功提示出现，列表/详情刷新
- [ ] 编辑模式数据正确回显
- [ ] 取消/关闭不脏数据

### 详情页/详情弹窗
- [ ] 数据完整展示，字典/状态字段正确翻译（不是裸 value）
- [ ] 图片/附件正常显示
- [ ] 关闭正常

### 通用（所有 PC 页面都要查）
- [ ] 控制台无 error/warn（含 Vue 运行时警告）
- [ ] 网络无 4xx/5xx/401
- [ ] 截图肉眼无错位、无溢出、无白屏、无样式错乱
- [ ] 关键路由/权限正常（不同角色 authorize 进入）

---

## 失败处理（修复循环）

验证发现问题 → 切回修改模式 → **只改导致问题的代码**（手术式修改，别顺手改无关）→ 切回验证模式重跑该项 → 直到客观证据通过。

- 改完一项就重验一项，不要攒一堆改动一起验（出问题难定位）。
- 修复也算"修改"，修复后的验证仍要和修复分开，不能"我刚改的这个，肯定对了"。

---

## ⚠️ 红线（违反 = 没验证）

1. **没连浏览器就宣称"验证通过"/"功能正常"** —— 禁止。
2. **只看源码/只 build 通过就当验证通过** —— 禁止。build 通过 ≠ 运行正确。
3. **边写边自我肯定**（"这行应该没问题"、"理论上对"）—— 禁止。要证据不要理论。
4. **复杂页面/核心逻辑改动不走独立验证 subagent**（路径 A）—— 强制走。
5. **验证只走 happy path**（只点一次新增、不试校验、不试异常）—— 不算通过。
6. **发现问题不修或修完不重验** —— 禁止。

---

## 自查清单

- [ ] 写完代码后明确"停手"，没有边写边自我宣告通过
- [ ] 复杂页面用了独立验证 subagent（路径 A）
- [ ] 用 chrome-devtools MCP 真实打开了页面（不是脑补、不是只 build）
- [ ] 至少查了：控制台 error、网络状态码、截图、一次完整交互
- [ ] 按对应页面类型的清单逐项核验，每项有客观证据
- [ ] 发现的问题已修复并重验通过
- [ ] 修改者 ≠ 验证者（或至少模式已显式切换，未混在一起）
