### 1.3 数据层契约（Java 后端必须 1:1 复刻）

- 存储模型：单表 `kv { room, path, value, ts }`，唯一键 `(room, path)`；`room` = coupleId
- 写操作 4 种语义：`set` 整路径覆盖 / `update` 顶层浅合并（`update(null)`=置空）/ `push` 塞一条 `{key:val}` / `remove` 删行
- 实时读：订阅单条 `(room, path)`，首推当前值 + 后续变更推送；**ts 拒旧防乱序**
- 断线：指数退避重连（1s→30s），重连前先拉一次回补
- 列表 = value 对象转 `[{id, ...v}]` 按 ts 升序
- 邀请码：6 位，字符集去掉易混 `I/O/0/1`
- 心跳：12s 一跳，30s 没心跳判离线（**H5 用 WebSocket 长连接后可废弃此机制，连接即在线、断开即离线**）

## 二、账号角色与数据继承方案（本项目的关键难点）

### 2.1 账号体系与角色设计（已定：账号密码登录）

H5 采用**「账号密码 + 角色系统 + 情侣空间绑定」**模型：

```
注册：账号（用户名，全局唯一）+ 密码 + 选角色（男生 boy / 女生 girl）+ 昵称 + 头像
绑定：一方创建「情侣空间」→ 得邀请码/邀请链接 → 另一方凭码加入 → 两账号绑定为空间成员

couples（情侣空间，保持单空间模型）
   ├── 成员槽 boy  ← 绑定一个 boy 角色账号
   └── 成员槽 girl ← 绑定一个 girl 角色账号
```

规则：
- **boy / girl 两个角色键原样保留**（这是所有历史数据的隔离键：`profile/boy`、`mood/{date}.boy`、`members/boy`、`stickers/boy`…），这样 kv 数据零转换即可继承
- 注册时选定角色，**注册后不可更改**（角色即历史数据键，换角色等于换人）
- 加入空间时校验角色与槽位匹配：boy 账号只能占 boy 槽、girl 账号只能占 girl 槽；对应槽位已被占则提示无法加入
- 一个账号同一时间只能绑定一个空间；「退出空间」后可重新创建/加入（历史数据保留在空间里）
- 展示层沿用原设计原则：**全站只显示网名+头像，不出现"男生/女生"字样**；boy/girl 仅作数据键
- 安全：密码 bcrypt 哈希存储；JWT 携带 `userId + role + coupleId`，服务端据此隔离数据；所有写操作校验"你必须是这个空间的成员"

### 2.2 历史数据继承（从微信云开发迁出）

```
微信云开发                       H5 (Java + SQLite)
─────────────                   ─────────────────
users(openid, nick, avatar)  →  创建两个正式账号（账号名/密码在迁移配置指定），
                                 角色按历史数据 boy/girl 指定，自动绑成情侣空间
couples(members:{boy:openid,   →  openid→角色映射关系存档备查
         girl:openid})
kv(room, path, value, ts)    →  原样整表迁入（room=coupleId 不变）
cloud://fileID 文件           →  下载转存到服务器磁盘，kv 里的 fileID 字符串批量改写为 /files/... URL
```

- 迁移工具：`love-h5/migrate/import.mjs`（Node 脚本，用云开发环境凭证拉全量数据+文件，产出 `data.json` + `files/`）；Java 侧提供导入接口（或启动时自动检测 `data/import.json` 一次性导入）
- 账号继承：迁移脚本直接创建两个正式账号并绑定为空间成员——装好即用新账号体系登录，**历史数据自动"认领"**
- 继承后立刻可用：聊天记录、每日心情历史、心愿、纪念日、真心话、游戏战绩、表情包收藏、戳一戳后缀、聊天背景——**全部原样出现**，且由对应角色账号"认领"
- 主题偏好（`lh5-theme` 原存本地）→ H5 首次登录时选一次，之后存账号

## 三、UX 重构设计（H5 全新样式）

### 3.1 设计原则

1. **手机优先，桌面前置适配**：竖屏移动端布局；PC 浏览器打开时限宽 480px 居中（两侧留主题色渐变氛围背景），一台电脑两个浏览器各登一个角色就能自测
2. **延续 8 套马卡龙主题**：`data-theme` 属性 + CSS 变量（小程序做不到的写法 H5 直接支持），8 套配色值原样搬运；主题切换即改 `<html data-theme>`，全站瞬时生效
3. **延续「UI 禁 emoji 图标」铁律**：一律用 Iconify（lucide 图标集）；心情 emoji 属产品数据不受限
4. **移动端交互范式**：底部 TabBar、底部半屏 Sheet（代替小程序弹层）、下拉刷新、长按操作菜单、安全区适配（iPhone 底部横条）
5. **高频功能提权**：聊天从「三级页面」提升为一级 Tab；今日心情内嵌到首页直接看/直接记，不用跳页
6. **信息可感知**：骨架屏、入场动画、对方上线/消息到达 toast、未读红点

## 四、技术架构

### 4.1 总体

```
浏览器（Vue 3 H5）
   │  HTTP REST（登录/上传/kv 写）
   │  WebSocket（实时：kv 变更推送 / 在线状态 / 站内通知）
   ▼
Spring Boot 3（Java 17，单 jar）
   ├─ AuthController      注册（选角色）/登录（账号密码→JWT）
   ├─ CoupleController    创建空间/加入空间/退出空间/邀请信息
   ├─ KvController        kv set/update/push/remove/get（语义与原 kvWrite 一致）
   ├─ FileController      图片/语音/文件上传 → 本地磁盘 ./data/files/
   ├─ TruthController     真心话抽题（62 题库入库）
   ├─ NotifyController    站内通知列表/已读
   ├─ WsSessionHub        WebSocket 会话管理：按 coupleId 广播、连接即在线
   ├─ KvService           kv 四种写语义 + ts + 变更事件发布
   ├─ ReminderScheduler   每日 9:00 扫纪念日 → 生成站内通知 + WS 实推
   └─ SQLite（单文件 ./data/love.db，备份=复制文件；预留 MySQL 配置可切）
```

### 4.2 技术选型（推荐，可改）

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3 + Vite | 与你现有 PBSF 工程同栈，维护成本最低 |
| UI 组件 | Vant 4（移动端） | 专为移动 H5 设计；备选 TDesign Mobile Vue |
| 状态/路由 | Pinia + vue-router | 标准组合 |
| 语言 | JavaScript（非 TS） | 与源码及你的习惯一致，降低维护门槛 |
| 图标 | @iconify/vue + lucide | 替代 emoji 图标 |
| 后端 | Spring Boot 3.x + MyBatis-Plus | 你熟悉的技术生态 |
| 实时 | 原生 WebSocket（JSON 协议） | 比 STOMP 轻，协议自己可控，前端好接 |
| 数据库 | SQLite（默认）/ MySQL（可选） | 家庭电脑零安装，数据就是一个文件 |
| 认证 | JWT（30 天）+ 密码 bcrypt | 账号密码体系最简可靠方案 |

### 4.3 WebSocket 协议设计

```jsonc
// 客户端 → 服务端
{ "op": "sub",   "path": "chat" }        // 订阅（可多次，前缀相交即推送）
{ "op": "unsub", "path": "chat" }
{ "op": "ping" }

// 服务端 → 客户端
{ "event": "kv",       "path": "chat", "value": {...}, "ts": 1724832000000 }
{ "event": "presence", "role": "girl", "online": true }
{ "event": "notify",   "type": "chat", "title": "…", "body": "…" }
{ "event": "pong" }
```

- **在线状态升级**：连接建立 → 服务端立即向对方广播 `presence online`；断开 → 广播 offline（小程序时代 12s 心跳 + 30s 超时猜测的机制整体废弃）
- 断线重连：指数退避（1s→30s），重连成功后对已订阅路径各拉一次回补（与原 store.js 行为一致）
- **ts 拒旧**在客户端保留：`ts` 小于缓存的推送直接丢弃
- 客户端 SDK：`web/src/core/store.js` 移植原 store.js 对外契约（`onValue/onList/getOnce/set/update/push/remove/transaction`），**业务页面代码几乎零改动成本**
- 连接鉴权：WS 建立时携带 JWT，服务端校验后绑定到对应 coupleId 频道

### 4.4 数据库设计

```sql
users    (id, username UNIQUE, password_hash, role 'boy'|'girl', nick, avatar,
          couple_id NULL, created_at, updated_at)   -- 空间成员绑定 = users.couple_id
couples (id, invite_code, created_by, created_at)   -- 成员由 users 按角色反查，一空间两槽
kv      (id, room, path, value TEXT/JSON, ts, UNIQUE(room, path))
notifications (id, room, target_role, type, title, body, created_at, read_at)
```
> kv 表 value 存 JSON 字符串，逻辑上与小程序 kv 集合完全同构——历史数据直接灌入。

### 4.5 REST API 一览（v0 草案）

```
POST /api/auth/register      {username, password, role, nick, avatar} → 注册（选角色）
POST /api/auth/login         {username, password} → JWT
GET  /api/me                 资料 + 空间绑定状态
PUT  /api/me/profile         {nick, avatar}（同时写 kv profile/{role} 触发实时）
POST /api/couple/create      创建空间（占自己角色槽）→ 邀请码+邀请链接
POST /api/couple/join        {inviteCode}（校验：码有效/未绑定/角色与槽位匹配/槽位为空）
POST /api/couple/leave       退出空间（解绑，历史数据保留在空间）
GET  /api/couple/invite      空间邀请码+链接（已绑定方查看）
GET  /api/kv?path=…          读单条
POST /api/kv                 {action: set|update|push|remove, path, …} → 写+WS 广播
GET  /api/kv/prefix?path=mood/  前缀批量拉（心情历史用）
POST /api/files              multipart 上传 → {url}
GET  /api/truth/draw?category=sweet   抽题
GET  /api/notifications      通知列表 / PUT 已读
```

## 五、部署方案

### 5.1 阶段一：部署在这台电脑（开发自测）

- 后端：`mvn spring-boot:run` → `http://localhost:8080`
- 前端：`npm run dev`（Vite 代理 /api 与 /ws）；正式构建后静态资源打进 Spring Boot jar，**一个 jar 就是整个网站**
- 自测方式：一台电脑开两个浏览器（或普通+无痕窗口）分别登录两个账号（boy/girl 角色），即可验证实时同步

### 5.2 阶段二：部署到家庭电脑

- `java -jar love-h5.jar` 开机自启（Windows 计划任务/NSSM 服务），局域网内手机访问 `http://192.168.x.x:8080`
- 需要外网访问时加内网穿透（推荐 Cloudflare Tunnel / frp），**拿到 HTTPS 后**以下能力才解锁：
  - 语音消息录制（MediaRecorder 要求安全上下文）
  - 浏览器系统通知、PWA 添加到主屏幕
  - localhost 与 HTTPS 下均可；纯局域网 HTTP 下这些功能自动降级隐藏（不影响其余功能）

### 5.3 数据安全

- SQLite 单文件 + `./data/files/` 目录，整体复制即备份；提供一键备份脚本（M5）
