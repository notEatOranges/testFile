# 多入口详情页：显示兜底禁用「全局当前项」坑点

## 现象
一个详情页（如报告页）能从**多个入口**进入，分别看不同实体的数据：
- 入口 A（首页）→ 看当前默认实体（如绑定孩子）
- 入口 B（列表/总览页）→ 看用户点选的某个实体

结果：从入口 B 进「非默认实体」时，页面头部（头像/姓名/班级等）**显示成了默认实体**，数据串号。而入口 A 进看着是对的——极具迷惑性，容易当成「首页正常、别的入口坏了」而查错方向。

## 根因
页面在「主数据未就绪」（接口未返回 / 该实体无数据导致主数据为 null）时，用一个**全局「当前默认项」**做显示兜底：

```js
// ❌ 错误：用全局 currentStudent 兜底
const stuName = computed(() => report.value?.studentName || studentStore.currentStudent?.name || '');
```

`studentStore.currentStudent` 是「当前默认绑定孩子」，与路由实际带入的实体**无关**。主数据 null 时，头部就回落到默认实体 → 串号。

关键陷阱：**查询接口用的 eduId 是对的（从路由取）**，所以「有数据的孩子」能看到正确报告；只有「无数据 / 加载中」的孩子才暴露串号。于是测试时若只拿有数据的孩子验证，根本发现不了。

## 通用规则（正确做法）
多入口详情页的**身份兜底**，一律按「路由带入的标识」反查，**禁用全局当前项**：

```js
// ✅ 用路由带入的 eduId 反查列表，兜底也是「路由那个实体」，不会串成默认项
const routeStudent = computed(() =>
  studentStore.students.find((s) => s.studentNum === eduId.value),
);
const stuName = computed(() => report.value?.studentName || routeStudent.value?.name || '');
```

判据：凡「页面能被带入不同 entityId 查看」的详情页，头部/侧栏的身份字段（头像、姓名、班级、性别图标等）兜底**只能跟路由 entityId 走**，不能取全局 `currentXxx`。

## 诊断方法
- 症状：「默认实体看着对、换一个实体就串成默认」= 八成本坑。
- grep 详情页里的 `currentStudent / currentUser / currentXxx` 兜底，凡出现在 computed/模板的身份字段里，都要换成按路由 entityId 反查。
- 验证：专门拿一个「主数据为空」的实体进页面，看头部是否串成默认实体。

## 本项目实例
- 项目：翼动同行（school-parent-mp，uni-app Vue3 mp-weixin）
- 路径：`packageMine/test-report/index.vue`（体测报告页）
- 链路：首页 → test-report（绑定孩子）；我的 → `packageMine/student-report/index.vue`（带 `studentNum+schoolId`）→ test-report（当前报告孩子）
- 错误点：`avatar/stuName/stuInfo` 主数据 null 时兜底 `studentStore.currentStudent`，导致从 student-report 进「非绑定孩子」且该生无体测数据时，头部串成默认绑定孩子。
- 修复：新增 `routeStudent`（按路由 `eduId(=studentNum)` 在 `studentStore.students` 反查），三个身份字段 + 性别全部改兜底 `routeStudent`。
- 注意：本坑不是 mp-weixin 平台陷阱，是纯数据流逻辑坑；但「页面多入口 + 全局当前项兜底」模式在多账号/多孩子/多租户详情页普遍存在，故入库。
