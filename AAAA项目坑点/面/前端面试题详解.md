## 一、浏览器渲染原理（Lesson 2）

### 01. 一段长任务，为什么有的时候会变成卡死？有的时候没有影响？

**核心原因：是否阻塞了主线程（Main Thread）。**

浏览器的渲染流水线（DOM → Style → Layout → Paint → Composite）和 JS 执行都运行在同一个主线程上。长任务是否会"卡死"页面，取决于以下因素：

1. **任务时长与帧预算的关系**
   - 浏览器需要保持 60fps，每帧预算约 **16.6ms**
   - 如果长任务超过 50ms，用户就能感知到延迟（RAIL 模型标准）
   - 如果长任务占据了整个帧甚至多帧，页面就会"卡死"

2. **任务的执行时机**
   - 如果长任务发生在用户交互（点击、滚动）之前，只是延迟首屏渲染
   - 如果发生在用户交互期间，就会阻断事件响应，表现为"卡死"

3. **解决方案**
   ```js
   // 方案一：任务拆分（Time Slicing）
   function splitTask(tasks) {
     return new Promise(resolve => {
       function doBatch(i) {
         const start = performance.now();
         while (i < tasks.length && performance.now() - start < 5) {
           tasks[i]();
           i++;
         }
         if (i < tasks.length) {
           requestAnimationFrame(() => doBatch(i));
         } else {
           resolve();
         }
       }
       doBatch(0);
     });
   }

   // 方案二：Web Worker（将计算密集型任务移出主线程）
   const worker = new Worker('heavy-task.js');
   worker.postMessage({ data });
   worker.onmessage = e => console.log(e.data);

   // 方案三：requestIdleCallback（利用空闲时间）
   requestIdleCallback(deadline => {
     while (deadline.timeRemaining() > 0 && tasks.length) {
       tasks.pop()();
     }
   });
   ```

### 02. 为什么我们的样式不生效？

样式不生效的原因非常多，按优先级从高到低排列：

1. **CSS 选择器优先级（Specificity）不足**
   ```
   !important > 内联 style (1000) > #id (100) > .class (10) > tag (1) > * (0)
   ```
   ```css
   /* 优先级 101，会覆盖 .box 的 background */
   #main .box { background: red; }
   .box { background: blue; }  /* 不生效 */
   ```

2. **CSS 层叠顺序** — 后声明的规则优先级更高（同优先级时）

3. **选择器拼写错误或路径不匹配**
   ```html
   <div class="myBox">Hello</div>
   <!-- 拼写不一致 -->
   <style>.mybox { color: red; }</style>  <!-- 不生效，大小写敏感 -->
   ```

4. **属性值语法错误** — 浏览器会直接忽略该声明
   ```css
   .box { color: rad; }    /* 拼写错误，忽略 */
   .box { font-size: 16; } /* 缺少单位，忽略 */
   ```

5. **DOM 还没加载就操作了样式**

6. **CSSOM 还没构建完就尝试读取样式**

7. **被行内样式 / JS 动态设置的样式覆盖**

8. **浏览器兼容性问题** — 某些 CSS 属性需要加前缀
   ```css
   .box {
     -webkit-transform: translateX(10px);
     transform: translateX(10px);
   }
   ```

**排查方法：** 打开 DevTools → Elements → Styles 面板，被划删除线的样式就是不生效的，旁边会提示原因。

### 03. 页面上的盒模型怎么变多了？

**核心知识点：box-sizing 的两种模式。**

```
┌─────────────────────────────────┐
│            margin               │
│  ┌───────────────────────────┐  │
│  │         border            │  │
│  │  ┌─────────────────────┐  │  │
│  │  │      padding        │  │  │
│  │  │  ┌───────────────┐  │  │  │
│  │  │  │   content     │  │  │  │
│  │  │  └───────────────┘  │  │  │
│  │  └─────────────────────┘  │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

- **`content-box`（默认）**：`width` 只包含 content 区域。设置 padding/border 会让元素实际尺寸变大。
  ```css
  .box {
    box-sizing: content-box; /* 默认 */
    width: 100px;
    padding: 10px;
    border: 5px solid;
    /* 实际占用宽度 = 100 + 10*2 + 5*2 = 130px */
  }
  ```

- **`border-box`（推荐）**：`width` 包含 content + padding + border。设置 padding/border 不会撑大元素。
  ```css
  .box {
    box-sizing: border-box;
    width: 100px;
    padding: 10px;
    border: 5px solid;
    /* 实际占用宽度 = 100px（content 被压缩到 70px） */
  }
  ```

**最佳实践：**
```css
*, *::before, *::after {
  box-sizing: border-box;
}
```

### 04. transform 的效率为什么有时候高？有时候就低？

**关键区别：是否触发了合成层（Compositing Only）。**

`transform` 高效的情况（只触发 Composite，不触发 Layout 和 Paint）：
```css
/* 这些操作由 GPU 合成线程处理，效率极高 */
.box {
  transform: translateX(100px);  /* 高效 */
  transform: translateY(50px);   /* 高效 */
  transform: scale(1.5);         /* 高效 */
  transform: rotate(45deg);      /* 高效 */
  opacity: 0.5;                  /* 高效 */
}
```

`transform` 低效的情况（触发了 Layout 回流）：
```css
/* 混合了会触发 Layout 的属性 */
.box {
  transform: translateX(100px);
  width: 200px;     /* 触发 Layout → 重新计算布局 */
  left: 50px;       /* 触发 Layout */
  top: 100px;       /* 触发 Layout */
  margin: 20px;     /* 触发 Layout */
}
```

**渲染流水线的三条路径：**

| 路径 | 触发条件 | 性能 |
|------|----------|------|
| **JS → Style → Layout → Paint → Composite** | 修改 width/height/margin/top/left 等 | 最差（全流程） |
| **JS → Style → Paint → Composite** | 修改 color/background/box-shadow 等 | 中等（跳过 Layout） |
| **JS → Style → Composite** | 修改 transform/opacity | 最优（跳过 Layout 和 Paint） |

**高效使用原则：**
- 动画只使用 `transform` 和 `opacity`
- 避免在动画中混合其他会触发 Layout 的属性

### 05. will-change 是什么？

`will-change` 是一个 CSS 属性，用于**提前告知浏览器某个属性即将发生变化**，让浏览器提前做好优化准备（如创建独立的合成层、分配 GPU 资源）。

```css
/* 告诉浏览器：这个元素即将发生 transform 变化 */
.box {
  will-change: transform;
}

/* 告诉浏览器：这个元素即将发生透明度变化 */
.fade-box {
  will-change: opacity;
}

/* 多个属性 */
.complex-box {
  will-change: transform, opacity;
}
```

**使用注意事项：**

1. **不要滥用** — 每个声明 `will-change` 的元素都会占用额外的内存和 GPU 资源
   ```css
   /* 错误：给所有元素都加 */
   * { will-change: transform; }  /* 绝对不要这样做！ */

   /* 正确：只在需要动画的元素上加 */
   .animated-box { will-change: transform; }
   ```

2. **不要长期声明** — 动画结束后应该移除
   ```js
   // 动画开始前设置
   element.style.willChange = 'transform';
   // 动画结束后移除
   element.addEventListener('transitionend', () => {
     element.style.willChange = 'auto';
   });
   ```

3. **本质原理**：`will-change` 会将元素提升到独立的合成层（Compositing Layer），由 GPU 单独处理，不干扰其他元素的渲染

### 06. 读取 style 属性会引发回流吗？回流究竟是什么？

**是的，某些读取操作确实会触发回流（强制同步布局 Forced Synchronous Layout）。**

**什么是回流（Reflow/Layout）？**

当 DOM 的几何属性（大小、位置）发生变化时，浏览器需要重新计算元素的布局，这个过程叫回流。

**强制同步布局的问题：**

```js
// 写 -> 读 -> 写 -> 读 ... 会导致多次回流（布局抖动 Layout Thrashing）
function badExample() {
  for (let i = 0; i < 100; i++) {
    el.style.width = '100px';           // 写（标记 dirty）
    console.log(el.offsetWidth);        // 读（强制回流计算！）
    el.style.width = '200px';           // 写（又标记 dirty）
    console.log(el.offsetWidth);        // 读（又一次强制回流！）
  }
}

// 正确做法：批量读取，再批量写入
function goodExample() {
  const widths = [];
  for (let i = 0; i < 100; i++) {
    widths.push(el.offsetWidth);  // 先全部读完
  }
  widths.forEach(w => {
    el.style.width = w + 'px';   // 再全部写入（只触发一次回流）
  });
}
```

**会触发回流的属性/方法：**

| 读取（会强制回流） | 写入（标记 dirty） |
|---|---|
| `offsetWidth`, `offsetHeight`, `offsetTop`, `offsetLeft` | 修改 width/height |
| `clientWidth`, `clientHeight` | 修改 padding/margin |
| `scrollWidth`, `scrollHeight`, `scrollTop` | 修改 position/top/left |
| `getComputedStyle()` | 修改 display |
| `getBoundingClientRect()` | 添加/删除 DOM 节点 |

**回流 vs 重绘（Repaint）：**
- **回流（Layout）**：元素的几何属性变了 → 需要重新计算布局 → 开销大
- **重绘（Paint）**：元素的视觉属性变了（颜色、背景等）→ 只需重新绘制 → 开销较小
- 回流一定会引起重绘，重绘不一定引起回流

### 07. CSSOM 究竟是什么？我们能读到哪些？能改变它吗？

**CSSOM（CSS Object Model）** 是浏览器将 CSS 样式表解析后生成的树形结构，和 DOM 树并行存在。

```
HTML 解析 → DOM Tree
CSS 解析 → CSSOM Tree
DOM + CSSOM → Render Tree → Layout → Paint → Composite
```

**CSSOM 的结构：**

```
document.stylesheets
├── CSSStyleSheet
│   ├── cssRules
│   │   ├── CSSStyleRule（普通规则）
│   │   ├── CSSMediaRule（媒体查询）
│   │   ├── CSSKeyframesRule（动画）
│   │   └── CSSImportRule（@import）
│   └── ...
└── ...
```

**我们能读到的：**
```js
 // 获取所有样式表
 document.styleSheets;           // StyleSheetList
 document.styleSheets[0].cssRules; // CSSRuleList

 // 获取某个规则的样式
 document.styleSheets[0].cssRules[0].style; // CSSStyleDeclaration

 // 获取计算后的样式
 getComputedStyle(element);       // 最终生效的所有样式
 getComputedStyle(element).color; // 具体属性值

 // 获取元素内联样式
 element.style;                   // 只读内联样式
```

**我们能改变的：**
```js
// 1. 修改内联样式
element.style.color = 'red';
element.style.cssText = 'color: red; font-size: 16px;';

// 2. 修改 class
element.classList.add('active');
element.classList.remove('hidden');
element.classList.toggle('open');

// 3. 动态操作样式表
const sheet = document.styleSheets[0];
sheet.insertRule('.box { color: red; }', sheet.cssRules.length);
sheet.deleteRule(0);

// 4. 动态创建样式表
const style = document.createElement('style');
style.textContent = '.box { color: red; }';
document.head.appendChild(style);
```

### 08. 合成线程是什么？它和主线程的关系是什么？

**浏览器中的线程分工：**

```
主线程（Main Thread）
├── 执行 JavaScript
├── 解析 HTML → 构建 DOM
├── 解析 CSS → 构建 CSSOM
├── 计算样式（Style）
├── 计算布局（Layout）
├── 绘制记录（Paint）—— 生成绘制指令列表
└── 分层（Layer）—— 确定哪些元素需要独立层

合成线程（Compositor Thread）—— 在 GPU 进程中
├── 接收主线程传来的绘制指令
├── 将图层分块（Tiling）
├── 光栅化（Rasterization）—— 将矢量图转为像素位图
├── 合成（Composite）—— 将所有图块组合成最终画面
└── 直接处理某些输入事件（如滚动）

├── 光栅化线程池（Raster Threads）
│   └── 多个线程并行光栅化不同图块
│
└── GPU 进程
    └── 最终完成合成与显示
```

**关键关系：**

1. **主线程被阻塞时**，合成线程仍然可以处理已光栅化的内容
   - 这就是为什么 `transform` 动画不卡：它在合成线程上执行，不走主线程
   - `position: fixed` 的元素在独立层上，滚动时合成线程直接处理

2. **合成线程独立处理的操作：**
   - CSS `transform` 动画
   - CSS `opacity` 动画
   - 滚动（已光栅化的区域）
   - `will-change` 提升的合成层

3. **需要主线程参与的操作：**
   - JavaScript 执行
   - DOM/CSSOM 修改
   - Layout 计算
   - Paint 绘制

### 09. 分层和分块是什么？

**分层（Layering）：**

浏览器将页面分成多个图层（Layer），每个图层独立渲染。分层的意义在于：当一个图层变化时，不需要重新渲染所有图层。

```
页面分层示例：
┌─────────────────────────┐
│  Layer 1: 背景层         │  ← 不动，不重绘
│  ┌───────────────────┐  │
│  │ Layer 2: 导航栏    │  │  ← 固定定位
│  └───────────────────┘  │
│  ┌───────────────────┐  │
│  │ Layer 3: 内容区    │  │  ← 滚动
│  │                   │  │
│  └───────────────────┘  │
│  ┌───┐                  │
│  │L4 │ 悬浮按钮         │  ← transform 动画
│  └───┘                  │
└─────────────────────────┘
```

**哪些情况会创建独立图层：**
- `position: fixed / sticky`
- `transform` 动画中的元素
- `opacity` 动画中的元素
- 设置了 `will-change` 的元素
- `<video>`, `<canvas>`, `<iframe>` 等元素
- CSS `filter` 属性

**分块（Tiling）：**

合成线程将每个图层切割成较小的图块（通常 256×256 或 512×512 像素）。

```
一个图层被分成多个图块：
┌────┬────┬────┬────┐
│ T1 │ T2 │ T3 │ T4 │
├────┼────┼────┼────┤
│ T5 │ T6 │ T7 │ T8 │
├────┼────┼────┼────┤
│ T9 │T10 │T11 │T12 │
└────┴────┴────┴────┘
```

**分块的意义：**
1. **按需光栅化** — 只光栅化视口内和即将进入视口的图块，不做无用功
2. **并行处理** — 多个光栅化线程同时处理不同的图块
3. **内存优化** — 不需要一次性把整个图层都光栅化

### 10. 光栅化是什么？

**光栅化（Rasterization）** 是将矢量图形（绘制指令）转换为像素位图（Bitmap）的过程。

```
绘制指令（矢量）                光栅化                   像素位图
┌─────────────┐            ┌─────────┐           ┌─────────────┐
│ drawRect    │            │         │           │ ■ ■ ■ ■ ■ ■ │
│ (10,10,     │  ──────►   │ Raster  │  ──────►  │ ■ ■ ■ ■ ■ ■ │
│  200, 100,  │            │ Thread  │           │ ■ ■ ■ ■ ■ ■ │
│  red)       │            │         │           │ ■ ■ ■ ■ ■ ■ │
└─────────────┘            └─────────┘           └─────────────┘
```

**光栅化的过程：**

1. **主线程**生成绘制指令（Paint 阶段）—— "画一个红色矩形在 (10,10)，大小 200×100"
2. **合成线程**将图层分块
3. **光栅化线程池**将每个图块的绘制指令转换为 GPU 纹理（像素矩阵）
4. 光栅化后的图块存入 **GPU 内存**
5. **合成线程**将所有光栅化后的图块合成最终画面，上屏显示

**关键点：**
- 光栅化是 CPU/GPU 密集型操作
- 只光栅化**视口内**和**即将进入视口**的图块（优先级调度）
- GPU 加速的光栅化比 CPU 快得多

### 11. link 元素和 script 元素谁在阻塞页面？

**核心：link 阻塞渲染，script 阻塞解析。**

```
HTML 解析流程：

遇到 <link css>
  → 暂停渲染（不暂停解析）
  → 下载 CSS → 构建 CSSOM
  → CSSOM + DOM 合并后才渲染
  → 结论：CSS 阻塞渲染（Render Tree 的构建依赖 CSSOM）

遇到 <script>（无 async/defer）
  → 暂停 HTML 解析
  → 下载 JS → 执行 JS
  → JS 执行完才继续解析 HTML
  → 结论：JS 阻塞 DOM 解析

遇到 <script async>
  → 不暂停解析，并行下载
  → 下载完后立即执行（暂停解析）
  → 执行顺序不确定（谁先下载完谁先执行）
  → 适合独立脚本（如统计、广告）

遇到 <script defer>
  → 不暂停解析，并行下载
  → 等 HTML 解析完后才执行（按顺序）
  → DOMContentLoaded 之前执行
  → 适合需要操作 DOM 的脚本
```

**总结表：**

| 资源 | 阻塞 HTML 解析 | 阻塞渲染 | 说明 |
|------|:---:|:---:|------|
| `<link css>` | 否 | **是** | 必须等 CSSOM 构建完才能渲染 |
| `<script>` | **是** | 是 | 下载+执行都阻塞解析 |
| `<script async>` | 否 | 部分 | 下载不阻塞，执行时阻塞 |
| `<script defer>` | 否 | 否 | 完全不阻塞，解析完后执行 |
| `<link css media="print">` | 否 | **否** | 不匹配的媒体查询不阻塞渲染 |

**最佳实践：**
```html
<head>
  <!-- CSS 放 head 尽早加载，尽早构建 CSSOM -->
  <link rel="stylesheet" href="style.css">

  <!-- JS 用 defer，不阻塞解析 -->
  <script defer src="app.js"></script>

  <!-- 独立脚本用 async -->
  <script async src="analytics.js"></script>
</head>
```

### 12. 属性值的计算过程

CSS 属性值从"声明"到"最终使用"经历以下阶段：

```
① 收集声明值（Declared Values）
   ↓ 从所有匹配的规则中收集属性值
② 级联（Cascaded Values）
   ↓ 按优先级、特殊性、来源选出"胜出"的值
③ 指定值（Specified Values）
   ↓ 如果没有级联值，使用默认值/继承值
④ 计算值（Computed Values）
   ↓ 将相对值转换为绝对值（em→px, var()替换等）
⑤ 使用值（Used Values）
   ↓ 布局计算后的最终值（百分比→具体像素值）
⑥ 实际值（Actual Values）
   ↓ 浏览器能直接使用的值（四舍五入等）
```

**详细说明：**

```css
/* 第一步：收集声明值 */
.parent { font-size: 16px; }
.child { font-size: 2em; }     /* 声明值 */
.child { font-size: 32px; }    /* 声明值（优先级更高） */

/* 第二步：级联 — 32px 胜出 */

/* 第三步：指定值 — 如果没有声明 color，则从父元素继承 */

/* 第四步：计算值 */
/* 2em → 32px（相对于父元素 16px） */
/* #fff → rgb(255, 255, 255) */

/* 第五步：使用值 */
/* width: 50% → width: 400px（父元素宽 800px 时） */

/* 第六步：实际值 */
/* border-width: 2.7px → 3px（四舍五入） */
```

**CSS 继承：**
- 可继承属性：`color`, `font-size`, `font-family`, `line-height`, `text-align`, `visibility`, `cursor` 等
- 不可继承属性：`width`, `height`, `margin`, `padding`, `border`, `background`, `display`, `position` 等
- `inherit` — 强制继承 | `initial` — 初始值 | `unset` — 可继承则继承，否则初始值 | `revert` — 浏览器默认值

## 二、属性描述符（Lesson 5）

### 01. Object.defineProperty 在干什么？

`Object.defineProperty()` 用于**精确地定义或修改一个对象的属性**，可以控制属性的各种行为（是否可改、可删、可遍历等）。

```js
const obj = {};

Object.defineProperty(obj, 'name', {
  value: '张三',          // 属性值
  writable: true,         // 是否可修改（默认 false）
  enumerable: true,       // 是否可遍历（默认 false）
  configurable: true,     // 是否可删除/重新配置（默认 false）
  // --- 或者使用访问器描述符 ---
  // get() { return this._name; },
  // set(val) { this._name = val; }
});

console.log(obj.name); // '张三'
```

**属性描述符分两类：**

| 类型 | 包含的键 | 用途 |
|------|---------|------|
| **数据描述符** | value, writable, enumerable, configurable | 直接存储值 |
| **访问器描述符** | get, set, enumerable, configurable | 通过函数控制读写 |

> 注意：两种描述符不能混用（不能同时有 value/writable 和 get/set）。

---

### 02. 如何实现只读属性？

```js
const config = {};

// 方式一：writable: false
Object.defineProperty(config, 'API_URL', {
  value: 'https://api.example.com',
  writable: false,       // 不可修改
  enumerable: true,
  configurable: false    // 不可重新配置
});

config.API_URL = 'hacked'; // 静默失败（严格模式下报错）
console.log(config.API_URL); // 仍然是 'https://api.example.com'

// 方式二：只用 getter，不提供 setter
Object.defineProperty(config, 'VERSION', {
  get() { return '1.0.0'; },
  enumerable: true
});

config.VERSION = '2.0.0'; // 静默失败，因为没有 setter
```

**面试加分点：** `const` 和 `Object.defineProperty` 的区别
- `const` 是声明层面的不可重赋值，但对象属性仍然可以修改
- `writable: false` 是属性层面的不可修改
- 两者配合使用才能实现真正的"常量"

### 03. 如何让属性不可被遍历？

```js
const user = {
  name: '张三',
  age: 25
};

Object.defineProperty(user, '_internalId', {
  value: 'secret-12345',
  enumerable: false,  // 关键：设为 false
  writable: true,
  configurable: true
});

console.log(Object.keys(user));       // ['name', 'age']
console.log(JSON.stringify(user));    // {"name":"张三","age":25}
for (const key in user) {
  console.log(key);                   // name, age（没有 _internalId）
}
console.log(user._internalId);        // 'secret-12345'（仍可访问）
console.log('length' in Object.keys(user)); // 只有 2 个
```

**应用场景：**
- Vue 2 中 `__ob__` 属性（观察者实例）设为不可枚举，避免被序列化和遍历
- 库/框架内部使用的"私有"属性
- 不希望出现在 `JSON.stringify` 结果中的属性

**面试延伸：** `Object.getOwnPropertyNames()` 可以获取包括不可枚举的属性
```js
Object.getOwnPropertyNames(user); // ['name', 'age', '_internalId']
```

### 04. 如何在读写属性时加入逻辑控制？

这是 **Vue 2 响应式系统的核心原理**（数据劫持 Data Hijacking）：

```js
// 简化版 Vue 2 响应式原理
function observe(obj) {
  if (typeof obj !== 'object' || obj === null) return;

  Object.keys(obj).forEach(key => {
    let value = obj[key];
    const deps = new Set(); // 简化版依赖收集

    Object.defineProperty(obj, key, {
      get() {
        // 读取时收集依赖
        console.log(`读取 ${key}`);
        if (currentWatcher) deps.add(currentWatcher);
        return value;
      },
      set(newVal) {
        if (newVal === value) return;
        console.log(`${key} 从 ${value} 变为 ${newVal}`);
        value = newVal;
        // 设置时触发更新
        deps.forEach(fn => fn());
      },
      enumerable: true,
      configurable: true
    });
  });
}

// 使用示例
const data = { count: 0, name: 'hello' };
observe(data);

data.count;        // 打印：读取 count
data.count = 1;    // 打印：count 从 0 变为 1
```

**Vue 2 响应式的局限性（面试必问）：**
```js
const vm = new Vue({
  data() {
    return { items: [1, 2, 3] }
  }
});

// 以下操作无法触发响应式更新：
vm.items[0] = 99;           // ❌ 数组索引直接赋值
vm.items.length = 0;        // ❌ 直接修改 length
vm.newProp = 'value';       // ❌ 动态添加新属性

// 正确做法：
Vue.set(vm.items, 0, 99);           // ✅
vm.items.splice(0);                  // ✅
Vue.set(vm, 'newProp', 'value');     // ✅
```

> Vue 3 使用 `Proxy` 解决了以上所有问题。

### 05. 冻结对象？

```js
const config = {
  API_URL: 'https://api.example.com',
  timeout: 5000,
  headers: {
    'Content-Type': 'application/json'
  }
};

// 浅冻结：只冻结第一层
Object.freeze(config);

config.API_URL = 'hacked';           // 静默失败
delete config.API_URL;               // 静默失败
config.newProp = 'value';            // 静默失败
config.headers['Content-Type'] = ''; // ⚠️ 仍然可以修改！嵌套对象未被冻结

// 深冻结：递归冻结所有层级
function deepFreeze(obj) {
  Object.keys(obj).forEach(key => {
    const value = obj[key];
    if (value && typeof value === 'object') {
      deepFreeze(value);
    }
  });
  return Object.freeze(obj);
}

deepFreeze(config);
config.headers['Content-Type'] = ''; // 现在也无法修改了
```

**相关 API 对比：**

| 方法 | 可修改属性值 | 可添加属性 | 可删除属性 | 可修改描述符 |
|------|:---:|:---:|:---:|:---:|
| 普通对象 | ✅ | ✅ | ✅ | ✅ |
| `Object.preventExtensions(obj)` | ✅ | ❌ | ✅ | ✅ |
| `Object.seal(obj)` | ✅ | ❌ | ❌ | ❌ |
| `Object.freeze(obj)` | ❌ | ❌ | ❌ | ❌ |

**检测方法：**
```js
Object.isFrozen(obj);           // 是否被冻结
Object.isSealed(obj);           // 是否被密封
Object.isExtensible(obj);       // 是否可扩展
```

**应用场景：**
- 常量配置对象
- Vuex 中的 state 冻结（防止直接修改）
- 传递给第三方库的配置（防止被篡改）

## 三、Vue 响应式原理（Lesson 6）

### Vue 的响应式到底是什么？

**一句话概括：** 当数据变化时，自动触发依赖该数据的视图更新。

#### Vue 2 响应式实现（Object.defineProperty）

```
                   ┌──────────────┐
                   │   Observer   │  递归遍历 data，用 defineProperty 劫持每个属性
                   └──────┬───────┘
                          │ 属性被读取时
                          ▼
                   ┌──────────────┐
                   │    Dep       │  每个属性都有一个 Dep（依赖收集器）
                   │  (subs: [])  │  收集所有依赖该属性的 Watcher
                   └──────┬───────┘
                          │ 属性被修改时
                          ▼
                   ┌──────────────┐
                   │   Watcher    │  每个组件对应一个 Watcher
                   │  (update)    │  收到通知后触发组件重新渲染
                   └──────┬───────┘
                          │
                          ▼
                   ┌──────────────┐
                   │  Virtual DOM │  新旧 VNode 对比（Diff 算法）
                   │   Patch      │  最小化 DOM 操作
                   └──────────────┘
```

```js
// Vue 2 响应式核心源码简化
class Dep {
  static target = null;
  constructor() { this.subs = []; }
  depend() { if (Dep.target) this.subs.push(Dep.target); }
  notify() { this.subs.forEach(w => w.update()); }
}

class Watcher {
  constructor(vm, exp, cb) {
    this.vm = vm;
    this.cb = cb;
    Dep.target = this;
    this.value = vm[exp]; // 触发 getter，收集依赖
    Dep.target = null;
  }
  update() {
    const newVal = this.vm[this.exp];
    this.cb(newVal);
  }
}

function defineReactive(obj, key, val) {
  const dep = new Dep();
  Object.defineProperty(obj, key, {
    get() {
      dep.depend();        // 收集依赖
      return val;
    },
    set(newVal) {
      if (newVal === val) return;
      val = newVal;
      dep.notify();        // 通知更新
    }
  });
}
```

#### Vue 3 响应式实现（Proxy）

```js
// Vue 3 响应式核心源码简化
function reactive(target) {
  return new Proxy(target, {
    get(obj, key, receiver) {
      track(obj, key);  // 收集依赖
      const result = Reflect.get(obj, key, receiver);
      return result && typeof result === 'object' ? reactive(result) : result;
    },
    set(obj, key, value, receiver) {
      const oldValue = obj[key];
      const result = Reflect.set(obj, key, value, receiver);
      if (oldValue !== value) {
        trigger(obj, key); // 触发更新
      }
      return result;
    },
    deleteProperty(obj, key) {
      const result = Reflect.deleteProperty(obj, key);
      trigger(obj, key);
      return result;
    }
  });
}
```

#### Vue 2 vs Vue 3 响应式对比（高频面试题）

| 特性 | Vue 2 (defineProperty) | Vue 3 (Proxy) |
|------|:---:|:---:|
| 监听新增属性 | ❌ 需要 `Vue.set()` | ✅ 自动监听 |
| 监听删除属性 | ❌ 需要 `Vue.delete()` | ✅ 自动监听 |
| 监听数组索引 | ❌ | ✅ |
| 监听数组长度 | ❌ | ✅ |
| 嵌套对象监听 | 初始化时递归（性能损耗） | 按需递归（懒代理） |
| 兼容性 | IE8+ | IE 不支持 |
| 性能 | 每个属性都需要 defineProperty | 整个对象一次 Proxy |

### 歌词滚动效果的实现思路（Lesson 3 拓展）

```js
// 核心思路：根据当前播放时间，找到对应歌词，滚动到可视区域
class LyricPlayer {
  constructor(lyrics, audio) {
    this.lyrics = lyrics;   // [{time: 0, text: '第一句'}, ...]
    this.audio = audio;
    this.currentIndex = -1;
  }

  play() {
    this.audio.play();
    this.audio.addEventListener('timeupdate', () => {
      const time = this.audio.currentTime;
      const index = this.findCurrentLine(time);
      if (index !== this.currentIndex) {
        this.currentIndex = index;
        this.scrollTo(index);
        this.highlight(index);
      }
    });
  }

  findCurrentLine(time) {
    for (let i = this.lyrics.length - 1; i >= 0; i--) {
      if (time >= this.lyrics[i].time) return i;
    }
    return 0;
  }

  scrollTo(index) {
    const el = document.querySelectorAll('.lyric-line')[index];
    el.scrollIntoView({ behavior: 'smooth', block: 'center' });
  }
}
```

### 购物车实现思路（Lesson 4 拓展）

```js
// 面向对象设计：将购物车拆分为独立的对象
class CartItem {
  constructor(product, quantity = 1) {
    this.product = product;
    this.quantity = quantity;
  }
  get totalPrice() {
    return this.product.price * this.quantity;
  }
  increase() { this.quantity++; }
  decrease() { if (this.quantity > 1) this.quantity--; }
}

class ShoppingCart {
  constructor() {
    this.items = new Map(); // productId -> CartItem
  }
  add(product) {
    const existing = this.items.get(product.id);
    if (existing) {
      existing.increase();
    } else {
      this.items.set(product.id, new CartItem(product));
    }
  }
  remove(productId) { this.items.delete(productId); }
  get total() {
    return [...this.items.values()].reduce((sum, item) => sum + item.totalPrice, 0);
  }
  get count() {
    return [...this.items.values()].reduce((sum, item) => sum + item.quantity, 0);
  }
}
```
