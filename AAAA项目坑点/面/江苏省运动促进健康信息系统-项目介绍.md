# 江苏省运动促进健康信息系统（TWRH）— 项目介绍

## 一、项目概述

**项目名称：** 江苏省运动促进健康信息系统（jsty_twrh_frontend）
**项目性质：** 政务类企业级管理系统（To G）
**业务领域：** 江苏省体育局「体卫融合」信息管理平台，覆盖全省 13 个地级市
**团队规模：** 前端参与 3-4 人
**我的角色：** 前端开发工程师

**核心业务模块：**
- 运动处方管理（开具、审核、打印、追踪）
- 处方师管理（注册、审核、培训、资质管理）
- 体育促进健康中心管理（机构认证、评审、公示）
- 培训管理（线上/线下培训、证书发放）
- 数据监测大屏（全省运动处方数据可视化）
- 系统管理（用户、角色、菜单、字典、日志等）

## 三、项目架构

### 3.1 Monorepo 架构

采用 pnpm workspace 实现 Monorepo，将系统按业务域拆分为 3 个独立子包：

```
jsty_twrh_frontend/
├── src/                          # 主应用入口（路由、状态、布局、公共组件）
├── packages/
│   ├── app-base/                 # @pbsf/app-base — 基础系统管理模块
│   │   ├── api/                  # 系统管理 API
│   │   └── views/                # 用户、角色、菜单、字典、日志、OSS 等
│   ├── app-twrh/                 # @pbsf/app-twrh — 体卫融合核心业务模块
│   │   ├── api/                  # 业务 API（50+ 接口文件）
│   │   ├── components/           # 业务组件（处方详情、健康问卷、审核记录等）
│   │   ├── hooks/                # 业务 Hooks
│   │   └── views/                # 业务页面（处方、培训、专项资金等）
│   └── app-dashboard/            # @pbsf/app-dashboard — 数据大屏模块
│       ├── api/                  # 大屏数据接口
│       ├── components/           # 大屏专用 UI 组件（CTable、CMap 等）
│       ├── config/               # 图表配色方案
│       ├── layout/               # 大屏独立布局
│       ├── router/               # 大屏独立路由
│       └── views/                # 大屏页面
```

**Monorepo 优势：**
- 各业务模块物理隔离，独立开发互不干扰
- 共享公共依赖和构建配置，减少重复
- 每个子包拥有独立的 api / views / components / hooks / router，职责清晰

### 3.2 动态路由与权限控制

**路由加载流程：**

```
用户登录 → 后端返回菜单树 → 前端递归处理 → 生成动态路由 → 注册到 Router
```

- 后端通过 `/system/menu/getRouters` 接口返回当前用户的菜单权限
- 前端 `permission.js`（路由守卫）拦截路由跳转，判断是否已加载路由
- `filterAsyncRouter` 函数递归将后端 component 路径转为懒加载组件
- 特殊组件映射：`Layout` → 布局组件、`ParentView` → 嵌套路由占位、`InnerLink` → iframe 内嵌

**权限控制方案：**
- **路由级权限：** 后端菜单控制页面级访问权限
- **按钮级权限：** `v-hasPermi` 指令 + `checkPermi()` 函数，校验权限字符串（如 `system:user:add`）
- **角色级权限：** `v-hasRole` 指令 + `checkRole()` 函数
- **超级权限：** 支持 `*:*:*` 超级权限和 `admin` 超级管理员角色

## 五、技术亮点

### 亮点 1：Three.js 3D 地图大屏

**这是本项目最突出的技术亮点。** 基于 Three.js 自主实现了一套完整的 3D 地图渲染引擎（约 710 行核心代码），用于数据大屏中心区域的江苏省地图立体展示。

**技术实现细节：**

1. **3D 场景搭建**
   - PerspectiveCamera 透视相机 + 多光源体系（方向光、环境光、点光源）
   - WebGLRenderer + CSS2DRenderer 双渲染器架构（CSS2D 用于在 3D 场景中渲染 HTML 标签）
   - OrbitControls 轨道控制器（限制旋转角度和缩放范围）

2. **地图立体化**
   - 使用 D3.js 的 `geoMercator` 投影将 GeoJSON 经纬度映射到 3D 空间坐标
   - Three.js `ExtrudeGeometry` 将 2D 多边形拉伸为 3D 立体区域（高度 15px）
   - 为每个地级市创建独立 Mesh，绑定 `properties` 存储行政区划编码

3. **炫光粒子效果**
   - 基于 Three.js Points 粒子系统，沿地图边界生成流动光效
   - 自定义 ShaderMaterial（vertex + fragment shader）实现粒子渐隐渐显
   - `CatmullRomCurve3` 样条曲线对边界点插值，实现平滑粒子运动路径

4. **波浪纹理动画**
   - Three.js Texture 的 `RepeatWrapping` + GSAP 动画驱动纹理偏移
   - 在地图侧面生成持续流动的波浪光效

5. **交互能力**
   - Raycaster 射线拾取：鼠标悬停高亮、点击交互
   - 自动轮播高亮：每 3 秒自动切换高亮各区域
   - 支持省→市下钻，共 14 个 GeoJSON 文件（1 省 + 13 市）

**面试话术：**
> "项目中我负责了数据大屏的核心模块——3D 地图。使用 Three.js 自研了一套地图渲染引擎，没有用现成的 3D 地图库。通过 D3 的地理投影将 GeoJSON 经纬度映射到 3D 空间，再用 ExtrudeGeometry 拉伸为立体模型。为了增强视觉效果，实现了粒子流光效果（自定义 Shader）和波浪纹理动画（GSAP 驱动）。交互方面用了 Raycaster 射线拾取做鼠标悬停高亮和自动轮播。"

### 亮点 2：ECharts 多维度数据可视化

大屏集成了丰富的 ECharts 图表矩阵：

- **2D 地图：** ECharts `registerMap` 注册 GeoJSON，`visualMap` 分段着色（按处方数量三档渐变），支持下钻到市级地图
- **渐变面积图：** 就诊流量趋势，`graphic.LinearGradient` 实现渐变填充，支持年/月度切换
- **饼图：** 就诊年龄分布 + 机构类型分布，自定义配色方案
- **柱状图：** 慢病干预跟踪，渐变柱体 + 圆角顶部
- **矩形树图（Treemap）：** 运动处方师地域分布
- **统一配色：** 16 色调色板集中管理

### 亮点 3：自研 PBSF 组件库 + 自动导入

项目封装了一套完整的业务组件库 `@pbsf/components`：

- 通过 `unplugin-vue-components` + 自定义 `PBSFResolver` 解析器实现全局自动注册
- 通过 `unplugin-auto-import` 自动导入 Vue / Vue Router API
- Element Plus 通过 `ElementPlusResolver` 按需自动导入（Sass 模式）
- 统一的 `PbsfConfigProvider` 全局配置注入（API 地址、上传配置、地图 Key）
- 形成了标准化的 CRUD 页面开发范式：`PbsfTableSearch` + `PbsfPagination` + `PbsfTableAction` + `useDict` + `useTable`

### 亮点 4：完整的多环境构建部署方案

- **6 套环境配置：** 开发 / 测试 / 生产 × 管理端 / 法人端

- 文件下载封装：`download()` / `downloadByGet()` 从 Content-Disposition 自动提取文件名
- RSA 加密登录：登录密码通过 `jsencrypt` 进行 RSA 公钥加密

### 亮点 6：数据大屏独立架构

大屏模块 `app-dashboard` 拥有完全独立的架构：
- 独立 Layout / Router / API / Components / Config

- 科技蓝视觉风格 + 自定义字体（DIN Alternate、阿里巴巴普惠体）

## 六、技术难点与解决方案

### 难点 1：3D 地图 GeoJSON 渲染与交互

**问题：** 需要将江苏省 GeoJSON 数据渲染为立体 3D 地图，同时实现鼠标交互和视觉效果。

**解决方案：**
- 使用 D3.js `geoMercator` 投影将 GeoJSON 经纬度转换为 3D 坐标
- Three.js `ExtrudeGeometry` 将 2D Shape 拉伸为 3D 实体
- `CSS2DRenderer` 双渲染器在 3D 场景中叠加 HTML 标签
- `Raycaster` 实现射线拾取，鼠标坐标转为 NDC 后与 Mesh 做交叉检测
- 粒子效果使用自定义 Shader + `BufferAttribute` 动态更新透明度

### 难点 2：大屏多分辨率自适应

**问题：** 数据大屏需要在各种分辨率（1920×1080、2560×1440、3840×2160）下保持视觉一致。

**解决方案：**
- 基于 1920×1080 设计稿，通过 `transform: scale(x, y)` 实现等比缩放
- 监听 `window.resize` 动态计算 scaleX / scaleY
- 通过 `provide/inject` 向子组件传递缩放比例
- 字体使用固定 px 值，随容器整体缩放

### 难点 3：动态路由与权限的动态加载

**问题：** 路由不是前端静态定义的，而是从后端 API 动态获取，需要处理多层嵌套和权限联动。

**解决方案：**
- 路由守卫中判断是否已加载（`addRoutes` 是否为空）
- `filterAsyncRouter` 递归处理菜单树：
  - `Layout` 映射为布局组件
  - `ParentView` 映射为嵌套路由占位（`<router-view />`）
  - `InnerLink` 映射为 iframe 内嵌组件
  - 其他组件路径使用 `import.meta.glob` 动态匹配 views 文件
- 使用 `import.meta.glob` 实现 packages 目录下的页面自动发现

### 难点 4：运动处方的复杂打印方案

**问题：** 运动处方需要精确打印为 A4 纸格式，包含签名图片、动态数据和复杂排版。

**解决方案：**
- 方案一（处方打印）：新窗口打开专用打印页面，CSS `@media print` + `210mm` 宽度适配 A4
  - JSON 配置驱动的动态打印模板（`layoutArr` 数组）
  - 签名图片 `onload` 后才触发 `window.print()`
  - 监听 `afterprint` 事件自动关闭窗口
- 方案二（培训封面）：Canvas 2D API 绘制封面（背景 + 文字 + 二维码）→ 转 PNG → printd 库打印
  - `@page { margin: 0 }` + `print-color-adjust: exact` 确保颜色准确

### 难点 5：复杂表单的未保存数据保护

**问题：** 处方编辑、单位编辑等复杂表单页面，用户误关闭或跳转导致数据丢失。

**解决方案：**
- `useUnsavedChangesGuard` Hook：
  - `setUnsavedChanges()` 标记页面有未保存更改
  - 注册全局回调 `window.__saveAndLeave` 供路由守卫调用
  - 路由离开前弹出「保存 / 不保存 / 取消」三按钮确认框
  - 组件卸载时自动清理状态，避免内存泄漏
- `FuDialog` 的 `beforeCloseApi` 支持关闭前拦截（如表单未保存提醒）

### 难点 6：Monorepo 构建优化

**问题：** 项目依赖庞大（Three.js + ECharts + D3 + wangEditor + Element Plus），打包体积大、构建慢。

**解决方案：**
- `manualChunks` 精细分包：大型库各自独立 chunk，利用浏览器缓存
- `unplugin-auto-import` + `ElementPlusResolver` 按需导入 Element Plus，减少包体积
- `vite-plugin-compression` 生产 gzip + brotli 双格式压缩
- `esbuild.drop` 移除 console / debugger
- `rollup-plugin-visualizer` 可视化分析构建产物，精准定位体积瓶颈

## 九、面试高频问题准备

### Q1：为什么要用 Monorepo？和微前端有什么区别？

**Monorepo（我们选的方案）：**
- 多个包在同一个仓库，共享工具链和依赖，构建配置统一
- 适合团队较小（3-4 人）、业务边界清晰的项目
- 使用 pnpm workspace，零运行时开销，编译时共享

**微前端（如 qiankun）：**
- 各子应用独立运行、独立部署、技术栈可异构
- 适合大团队、需要独立发布的场景
- 引入运行时沙箱、样式隔离等额外复杂度

**我们选择 Monorepo 的原因：** 团队规模小、技术栈统一、各模块无需独立部署，Monorepo 在开发体验和构建效率上更有优势。

### Q2：动态路由是怎么实现的？

1. 用户登录后，路由守卫拦截首次跳转
2. 调用 `/system/menu/getRouters` 获取当前用户的菜单树
3. `filterAsyncRouter` 递归处理菜单数据：
   - 将后端的 component 字符串（如 `app-twrh/views/xxx/index`）转为懒加载 import
   - `Layout` → `@/layout/index`，`ParentView` → `@/components/ParentView`
4. `router.addRoute()` 动态注册路由
5. 存入 Pinia 标记已加载，避免重复请求

### Q3：3D 地图是怎么实现的？

1. 加载 GeoJSON 数据（14 个文件：江苏省 + 13 个地级市）
2. D3 `geoMercator` 投影将经纬度转为 XZ 平面坐标
3. Three.js `Shape` + `ExtrudeGeometry` 拉伸为 3D 立体区域
4. 自定义 Shader 粒子系统实现边界流光效果
5. GSAP 驱动纹理偏移实现波浪动画
6. Raycaster 射线拾取实现鼠标交互

### Q4：按钮级权限怎么实现的？

- 登录时后端返回用户权限列表（如 `['system:user:add', 'system:user:edit']`）
- 存入 Pinia 的 `permissions` 数组
- `v-hasPermi` 自定义指令：比对当前元素绑定的权限字符串
- `checkPermi()` 函数：在 JS 逻辑中做权限判断
- 超级管理员拥有 `*:*:*` 权限，所有校验直接通过

### Q5：Axios 请求封装了哪些能力？

- **请求拦截：** 自动注入 Bearer Token、GET 参数序列化（qs）、POST 防重复提交（1 秒间隔校验）
- **响应拦截：** 统一错误处理（401 弹窗重新登录、500 错误提示）、文件流直接返回
- **文件下载：** POST/GET 两种方式，从 Content-Disposition 自动提取文件名
- **RSA 加密：** 登录密码使用 `jsencrypt` RSA 公钥加密后传输

### Q6：大屏怎么做自适应的？

- 基于 1920×1080 设计稿，通过 `transform: scale(scaleX, scaleY)` 等比缩放
- 监听 `window.resize` 动态计算缩放比例
- `provide/inject` 向子组件传递缩放比例，子组件可据此调整交互区域
- 不用 rem / vw 方案，因为大屏需要精确像素控制

### Q7：FuDialog 组件的设计思路？

- **Register 模式**（类似 Ant Design Vue 的 useModal）：
  - 子组件通过 `useFuDialog()` 获取 `[register, { open, close, setProps }]`
  - 父组件将 `register` 传给 `<FuDialog :onRegister="register">`
  - 通过 `setProps` 动态修改对话框属性，无需 v-model
- **异步提交：** 传入 `confirmApi`，自动处理 loading + 成功/失败
- **关闭拦截：** `beforeCloseApi` 支持异步判断是否允许关闭

### Q8：项目做了哪些构建优化？

1. **分包策略：** `manualChunks` 将大型库（three / echarts / element / wangeditor）各自独立打包，利用浏览器缓存
2. **Tree Shaking：** Element Plus 通过 `ElementPlusResolver` 按需导入
3. **代码压缩：** esbuild drop console/debugger + terser 压缩
4. **资源压缩：** vite-plugin-compression 生成 gzip + brotli
5. **Legacy 兼容：** @vitejs/plugin-legacy 为旧浏览器生成降级代码
6. **产物分析：** rollup-plugin-visualizer 生成 stats.html 可视化报告
