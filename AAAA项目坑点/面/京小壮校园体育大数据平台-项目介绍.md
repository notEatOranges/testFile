# 京小壮校园体育大数据平台（PBSF）- 项目技术介绍

## 一、项目概述

**项目名称**：京小壮成志体育大数据平台（公共基础服务框架 PBSF）

**项目简介**：该项目是一套面向北京市多所中小学（清华附小、京西实验学校、大峪中学分校、门头沟区等）的校园体育数据可视化大屏系统。系统通过采集学生体质测试数据、日常锻炼数据、运动轨迹等，进行多维度数据分析和可视化展示，帮助学校和教育管理部门实时掌握学生体质健康水平，为体育教学改革提供数据支撑。

**核心业务场景**：
- 校园体育大屏数据展示（体测数据概览、日常锻炼情况、运动趋势分析）
- 班级画像（学生体质数据的桑基图、雷达图等多维度分析）
- 个人运动档案（学生个体的运动数据追踪）
- 体测/体锻一张图（体质测试和锻炼的可视化总览）
- 运动风云榜（学生运动排名）
- AI 智能助手（京小壮 ChatBI，基于大模型的智能问答）
- 人脸识别登录（大屏终端通过摄像头刷脸登录）

## 四、核心技术亮点

### 4.1 Three.js 3D 地图可视化

**难点**：需要将 GeoJSON 地理数据渲染为 3D 拓扑地图，并实现交互效果。

**实现方案**：
- 使用 **D3.js geoMercator** 投影将 GeoJSON 经纬度坐标转换为屏幕坐标
- 通过 **Three.js** 将 2D 地图数据挤出（ExtrudeGeometry）为 3D 立体地图
- 实现了 `Basic3D` 类封装了完整的 3D 渲染管线：Scene → PerspectiveCamera → WebGLRenderer → OrbitControls（轨道控制器）
- 使用 **CSS2DRenderer** 在 3D 场景上叠加 HTML 标签（区域名称、数据标注）
- 通过 **Raycaster** 实现 3D 场景的鼠标交互（区域悬浮高亮、点击选中）
- 支持 **光线追踪**（PointLight、DirectionalLight、AmbientLight）营造真实的 3D 光影效果
- 自定义 **ShaderMaterial** 实现动态流光特效（城市间的连线动画）

**面试话术**：

> 项目中需要在大屏上展示区域地图，我使用 Three.js + D3.js 实现了 3D 地图可视化。通过 D3 的 geoMercator 投影把 GeoJSON 坐标映射到屏幕坐标，再用 Three.js 的 ExtrudeGeometry 将平面地图挤出为 3D 模型。同时用 CSS2DRenderer 做 HTML 标签叠加，用 Raycaster 实现鼠标交互。为了提升性能，我把 3D 渲染逻辑封装成了 Basic3D 类，统一管理场景、相机、渲染器和灯光。

### 4.2 AI 智能助手（ChatBI）- SSE 流式对话

**难点**：需要对接大模型 API，实现类似 ChatGPT 的流式对话体验。

**实现方案**：
- 封装了独立的 `@pbsf/app-vue-chat` 组件包，支持 **SSE（Server-Sent Events）流式输出**
- 实现 `useChat` 组合式函数，管理对话消息列表、发送状态、流式响应
- 支持 **Markdown 渲染**（marked）+ **代码高亮**（highlight.js）+ **数学公式**（KaTeX）
- 实现打字机效果（typewriter），逐字显示 AI 回复
- 支持 **多轮对话**、**历史记录**、**文件上传**、**重新生成**、**停止响应**
- 使用 **VueUse 的 useEventBus** 实现跨组件通信

**面试话术**：

> 项目中集成了 AI 智能助手功能，我封装了一个独立的 Chat 组件库。基于 SSE 协议实现了流式输出，用户发送消息后 AI 回复会逐字显示，体验类似 ChatGPT。组件支持 Markdown 渲染、代码高亮、数学公式显示，以及多轮对话、历史记录、文件上传等功能。我把核心逻辑抽离成 useChat 组合式函数，让聊天功能可以在不同页面快速复用。

### 4.3 多租户多环境打包架构

**难点**：一套代码需要部署到 10+ 所不同的学校，每个学校有不同的 API 地址、租户 ID、主题配置。

**实现方案**：
- 设计了 **13 套 .env 配置文件**（development、production、test、demo、qhfx、sq、jxsy、dyzx、ccj、mtg、cyq、yzq、hdq）
- 每套环境配置独立的 `VITE_APP_BASE_API`、`VITE_APP_TENANT_ID`、`VITE_APP_PUBLIC_PATH`
- 开发了 `buildAll.mjs` 批量构建脚本，一键打包所有环境并自动生成 ZIP 压缩包
- 通过 `script/set-app-argv.mjs` 动态设置环境变量
- 使用 Vite 的 `loadEnv(mode)` 在构建时注入不同配置

**面试话术**：

> 项目采用多租户架构，一套代码部署到十几所学校。我设计了基于 Vite 环境变量的多环境打包方案，每所学校一套 .env 配置文件。同时写了一个批量构建脚本，可以一键打包所有学校的版本并自动压缩成 ZIP，大大减少了发布工作量。

### 4.4 人脸识别登录系统

**难点**：大屏终端需要支持学生通过摄像头刷脸快速登录，无需手动输入账号密码。

**实现方案**：
- 使用 **face-api.js** 加载 TinyFaceDetector、FaceLandmark68Net、FaceRecognitionNet 三个模型
- 通过 `navigator.mediaDevices.getUserMedia` 调用摄像头，支持前置/后置摄像头切换
- 模型文件放置在 `public/weights` 目录，首次加载后缓存
- 捕获人脸图像后转为 Base64 发送至后端进行人脸比对
- 封装了 `Face/index.vue` 组件，暴露 `capture` 方法供父组件调用
- 封装了 `faceHelper.js` 管理模型加载状态，避免重复加载

**面试话术**：

> 大屏终端需要刷脸登录，我使用 face-api.js 实现了人脸检测功能。通过 getUserMedia 调用摄像头，加载轻量级的 TinyFaceDetector 模型检测人脸位置，捕获图像后 Base64 编码发送到后端比对。模型文件放在 public 目录，首次使用时加载，之后走浏览器缓存。

### 4.5 大屏自适应与数据可视化

**难点**：大屏数据展示需要适配不同分辨率的屏幕，且图表类型多样。

**实现方案**：
- 使用 **ECharts** 实现多种图表：饼图、折线图、柱状图、桑基图、雷达图、仪表盘
- 自定义封装了 `CText`（数据文字组件）、`CTable`（数据表格无缝滚动）、`CMap`（3D 地图）
- 使用 `provide/inject` 实现跨层级组件数据共享，避免 prop drilling
- 通过 CSS Module（`$s()` 函数）实现样式隔离
- 使用 **vue3-seamless-scroll** 实现列表自动滚动
- 使用 **Swiper** 实现轮播切换效果
- 使用 **GSAP** 动画引擎实现数字翻牌、进度条动画等大屏动效
- 使用 **@kjgl77/datav-vue3** 数据大屏装饰组件

**面试话术**：

> 大屏展示涉及多种图表，我用 ECharts 实现了饼图、折线图、桑基图、雷达图等。为了解决组件间数据传递问题，我使用 provide/inject 做跨层级数据共享。大屏的动画效果通过 GSAP 实现，包括数字翻牌和进度条动画。列表数据使用 vue3-seamless-scroll 自动滚动展示。

### 4.6 自动登录超时与用户活动检测

**难点**：大屏部署在学校公共区域，需要在无人操作时自动退出登录保护隐私。

**实现方案**：
- 封装了 `loginHelper` 模块，实现了完整的登录超时管理
- 监听用户活动事件（鼠标移动/点击、键盘输入、触摸操作），使用 **lodash throttle** 防抖续期
- 超时后自动调用后端退出接口并清除本地状态
- 支持倒计时回调，UI 层可显示剩余时间
- 区分 PC/BS 设备类型，PC 设备跳过自动退出逻辑
- 路由守卫中集成登录状态检查，未登录自动跳转到登录页

### 4.7 Axios 二次封装与文件下载

**难点**：需要统一处理请求/响应拦截、Token 自动注入、错误码处理、文件下载进度。

**实现方案**：
- 使用 Axios 工厂模式（`createAxios`），支持创建多个实例（默认实例、apiService 实例）
- **请求拦截器**：自动注入 Bearer Token 和 tenant-id 租户标识
- **响应拦截器**：统一处理 200/401/500 等状态码，401 时自动清除登录状态
- 实现 **三种文件下载方式**：
  - `download1`：传统 Axios Blob 下载
  - `downloadByGet`：GET 方式下载
  - `download`：基于 **Fetch API + ReadableStream** 实现下载进度显示，使用 ElNotification 展示进度条，支持**取消下载**（AbortController）
- 使用 **file-saver** 处理文件保存，自动解析 Content-Disposition 获取文件名

**面试话术**：

> 我对 Axios 做了深度封装，使用工厂模式创建多个实例。请求拦截器自动注入 Token 和租户 ID，响应拦截器统一处理错误码。文件下载这块，我用 Fetch API 的 ReadableStream 实现了下载进度展示，用户可以看到实时进度并取消下载。这个方案比传统 Axios Blob 下载体验好很多。

## 九、项目难点总结（面试重点）

### 难点一：3D 地图渲染性能优化

**问题**：Three.js 渲染 3D 地图时，GeoJSON 数据量大，模型面数多，导致帧率低。

**方案**：
- 使用 BufferGeometry 代替传统 Geometry，减少内存占用
- 合并相邻区域的几何体，减少 draw call
- OrbitControls 限制了缩放范围和旋转角度，避免渲染过多细节
- 使用轻量级的 MeshPhongMaterial 代替 PBR 材质

### 难点二：多租户多环境构建

**问题**：一套代码需要根据不同学校打出不同包，每个学校的 API 地址、租户 ID、主题、标题都不同。

**方案**：
- 使用 Vite 的 mode 机制，每个学校一套 .env 文件
- 编写 `buildAll.mjs` 批量构建脚本，自动清理、构建、压缩
- 构建产物自动打包成带时间戳的 ZIP 文件，方便运维部署

### 难点三：大屏终端无人值守自动退出

**问题**：大屏放置在公共区域，学生在操作完毕后不会主动退出，下一个学生可能看到上一个人的数据。

**方案**：
- 监听用户活动事件（鼠标、键盘、触摸），使用 throttle 防抖续期
- 设置超时定时器，超时后自动调用登出接口
- 支持倒计时回调，可在 UI 上显示剩余时间提醒用户
- 通过路由守卫实现登录状态检查，确保未登录用户无法访问受保护页面

### 难点四：SSE 流式对话的前端实现

**问题**：对接大模型 API 时，需要实现流式输出，逐字显示 AI 回复，同时支持 Markdown 和代码高亮。

**方案**：
- 基于 SSE 协议实现流式数据接收
- 将 AI 回复按字符/分块追加到消息列表，触发 Vue 响应式更新
- 使用 marked 库将 Markdown 文本实时转换为 HTML
- highlight.js 进行代码语法高亮
- KaTeX 渲染数学公式

### 难点五：大屏数据实时更新与性能

**问题**：大屏页面组件众多（首页有 8+ 个卡片组件），每个卡片都有自己的 ECharts 实例，数据量大时页面卡顿。

**方案**：
- 使用 `provide/inject` 做数据分发，避免每个组件独立请求
- ECharts 实例按需创建，组件销毁时 dispose 释放内存
- 使用 `nextTick` 确保 DOM 更新后再初始化图表
- 使用 `Promise.all` 并行请求多个接口，减少等待时间
- 大屏切换班级时使用 ElLoading 全屏 loading，提升用户体验感知
