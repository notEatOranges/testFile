# 后端接口 数字/金额字段传空串报错 → 须整字段省略 坑点

## 现象
表单里某数字/金额字段（如 `originalPrice`、`price`、`qty`）非必填，用户不填时前端初始化为 `''`（空字符串），提交后端报错（500 / 参数类型错误 / 反序列化失败）。改成不填就不传该字段后即正常。

## 根本原因
后端 DTO 字段是 `BigDecimal` / `Integer` / `Long` 等数值类型。前端用 `JSON.stringify` 把 `''` 当字符串发过去，Jackson 等反序列化器**无法把空串转成数值**（能转 `null`，但不能转 `""`），于是抛异常。

- `null` / 字段不存在：后端一般能接受（数值引用类型默认 `null`）。
- `""`：是合法 JSON 字符串，但不是合法数值 → 报错。

所以“不填”的正确表达是**不传该字段**（或传 `null`），而不是传 `""`。

## 通用规则（红线）
- 非必填的数值字段，提交前必须做处理：**空值时从 payload 里删掉该字段**，不要留 `''`。
- 前端表单初始化数值字段用 `''` 没问题（给 `v-model` 占位），但**提交前要洗**。
- 批量接口（`insertBatch`，body 是数组 `[{...},{...}]`）更易踩：`map` 里直接 `...x` 展开会把每行的空串原样带过去，要逐行处理。
- 判断“空值”要与校验器一致：常见 `if (!value)` 即视作空（`''`/`null`/`undefined` 都算）。注意字符串 `"0"` 是 truthy，不会被误删，0 价场景仍会正常提交。

## 修复模板
对象展开时把目标字段单独拎出，按需回填：
```js
const params = formData.tableData.map(x => {
  const { originalPrice, ...rest } = x   // 拎出来，不让 ...rest 带空串
  return {
    ...rest,
    ...(originalPrice ? { originalPrice } : {})   // 有值才传
  }
})
```
等价写法（构建后删字段）：
```js
const item = { ...x }
if (!item.originalPrice) delete item.originalPrice
```

## 排查步骤
1. F12 Network → 看报错接口的 Request Payload，找到值为 `""` 的数字字段。
2. 确认该字段在表单初始化（如 `info = { originalPrice: '' }`）或 `v-model` 默认值处被置为空串。
3. 在组装提交参数处（`map` / `Object.assign` / 展开）按上面模板改成“空则省略”。
4. 重新提交，确认 payload 里该字段已消失，后端不再报错。

## 本项目实例
- 项目：**青少年智能培训管理系统 (Qsntypx-q)**（Vue3 + Element Plus）
- 接口：`POST /api/course/schedule/insertBatch`（批量新增课时排期，body 为数组）
- 文件：`src/pages/comp-manage/course-manage/components/dialog.period.vue`
- 问题写法：新增行时 `originalPrice: ''` 初始化，`confirm()` 里 `formData.tableData.map(x => ({ ...x, ... }))` 把空串原样展开 → 后端报错。
- 修复：`map` 里解构出 `originalPrice`，仅 `originalPrice ? { originalPrice } : {}` 时回填，空值不传。
- 校验器 `originalPriceVali` 用 `if (!value) callback()` 判空，与“空则省略”逻辑一致；`"0"` 为 truthy 不受影响。
